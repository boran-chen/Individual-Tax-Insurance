# 保险代理人佣金个税申报数据管理系统

基于《保险代理人佣金个税申报数据管理系统 PRD V1.0》实现的可运行网页应用，并在 V1.0 之上补齐了 PRD 中列为“规划中”的**回传 → 自动比对 → 差异拦截 → 留存归集**闭环。

- 集团管理员：上传月度佣金总表、校验、分省拆分、发布、下载、查看回传进度与归集。
- 省级负责人：只查看/下载本人负责组织的四 Sheet 申报数据；下载加工后回传；查看比对结果。
- 系统：按“证件号码 + 姓名”逐条比对回传数据与原始数据，有差异不通过；零差异才进入当月归集。

## 快速开始

```bash
npm install
npm run setup
npm run generate:sample
npm run dev
```

打开 http://localhost:3000 。

> 本仓库在当前环境中通过用户终端执行 `npm install`（构建会话的沙箱禁止访问 npm registry）；在普通开发机上直接执行即可。

### 端到端演示

1. 管理员登录 → 新建上传 → 选择 `samples/2026-07_佣金总表_样例.xlsx`。
2. 确认月份 `2026-07`（系统会从文件名建议，最终以确认值为准）。
3. 查看字段识别、异常清单、省份分布和四个看板，然后发布批次。
4. 用 `gd_user` 登录 → 我的批次 → 下载广东省四 Sheet 文件。
5. 回传与结果 → 上传 `samples/2026-07_广东_回传_正确.xlsx` → 自动比对通过并进入归集。
6. 再次上传 `samples/2026-07_广东_回传_篡改.xlsx` → 展示金额不一致/缺少记录，不通过，归集被排除。
7. 管理员 → 回传与归集 → 查看已通过组织合计、未归集原因，并导出归集 Excel。

样例文件包含深圳优先、广东、未知省份、负数、空金额、文本金额、无效入职月份、缺证件号、前导零证件号、重复记录等边界数据。

## 技术栈

- Next.js 15（App Router）+ React 19 + TypeScript
- SQLite：Node 内置 `node:sqlite`（WAL 模式），无需安装数据库或原生模块
- Excel：`exceljs` 流式读写
- 鉴权：HMAC-SHA256 签名会话 Cookie + `crypto.scrypt` 密码哈希
- 测试：Vitest（规则单测 + SQLite 集成测试）
- 样式：原生 CSS 设计系统，无 UI 框架

## 业务规则实现

### 月份与有效数据

- 管理员确认月份 M（`YYYY-MM`），文件名为建议值；跨年自动计算 M+1（如 2026-12 → 2027-01）。
- 应税所得可转数值且 ≥ 0 为有效（0 有效）；负数标记“负数排除”；空值/非数值进入异常清单，不按 0 处理。
- 入职月份支持 `YYYY-MM`、`YYYY/M`、`YYYY年M月`、Excel 日期/序列值；无法识别时保留在汇总/劳动报酬，但不进入新增/转非。
- 姓名、证照类型、证照号码任一为空：保留在汇总和异常清单，不进入三个导入 Sheet。

### 组织拆分

- 键为“渠道机构所在省”，先做安全清洗（去首尾/全半角空格），不改写原始值。
- 含“深圳”→ 深圳市分公司（优先于广东）；其次含“广东”→ 广东省分公司；其他查可维护的省份映射表；空/未知 → 组织归属异常。
- 守恒校验：有效记录数 = 已归属 + 归属异常；各组织应税所得合计 = 已归属有效数据合计。不通过不能发布。

### 四个 Sheet

| Sheet | 规则 |
| --- | --- |
| 1新增人员信息导入 | 入职月份 = M+1 |
| 2转非 | 入职月份 = M |
| 3劳动报酬收入 | 全部有效且身份完整记录；固定 13 列；收入 = 应税所得；所得项目固定“保险营销员佣金收入” |
| 4汇总 | 该组织全部有效源记录，保留源表列顺序和原值 |

导出文件名：`{YYYY-MM}_{组织名称}_佣金个税申报数据_V{版本}.xlsx`；固定四个 Sheet、无默认空白 Sheet；证照号码文本格式；空数据仍写表头。

### 权限与审计

- 所有页面、接口、导出均在服务端按会话组织权限过滤；批次 ID/组织 ID/URL 不作为授权凭据。
- 证照号码 AES-256-GCM 加密存储，页面默认掩码（前 3 后 4），完整值仅出现在授权导出文件中。
- 上传、发布、作废、下载、回传、比对、账号与权限变更、配置变更全部写审计日志；日志不记录完整证照号码。
- 停用账号/改密会递增 `session_version`，旧会话立即失效。

### 回传比对

- 省负责人对本人组织的已发布批次下载文件，加工后回传 `.xlsx`。
- 默认读取“3劳动报酬收入”Sheet；工作表名、列别名、金额容差可在“系统配置 → 回传模板”调整，兼容扣缴端导出模板。
- 以“证件号码 + 姓名”为键，金额按分精确比对；同一人多条佣金按金额多重集处理。
- 差异类型：回传缺少、回传多出、金额不一致、姓名/证照类型不一致、重复记录。任一条差异即不通过。
- 通过后保存回传行并写入归集；不通过保留差异明细和历史版本，可重新回传。
- 归集以每组织**最新一次回传**为准：最新为不通过/未回传的组织会从当月归集中剔除，不会保留旧版本的归集数据。

## 配置

| 配置项 | 位置 | 说明 |
| --- | --- | --- |
| 字段别名 | 管理员 → 系统配置 → 字段别名 | 追加到默认别名之后；用于识别源表表头 |
| 回传模板 | 管理员 → 系统配置 → 回传模板 | JSON：sheetNames、columns、headerRow、toleranceCents |
| 省份映射 | 管理员 → 省份映射 | 源值 → 标准组织；深圳/广东特殊规则始终优先 |
| 上传限制 | `.env.local` | `MAX_UPLOAD_MB`、`MAX_ROWS` |
| 加密/会话密钥 | `.env.local` | `APP_ENCRYPTION_KEY`、`APP_ID_HASH_KEY`、`APP_SESSION_SECRET`，由 `npm run setup` 生成 |

规则版本固定为 `1.0.0`，批次、导出和比对记录均保存规则版本，便于追溯。

## 数据与备份

- 业务数据：`data/app.db`（SQLite，WAL）；原文件/导出/回传文件：`storage/`。
- 备份时同时备份 `data/` 与 `storage/`，并保证两者时间点一致。
- `.env.local` 含加密密钥，丢失后已加密的证照号码无法解密，需单独安全备份。

## 已知边界

- 当前没有真实佣金总表样表，字段位置、别名、省份取值均为**可配置默认值**；拿到真实样表后请在“系统配置/省份映射”中联调并冻结规则版本。
- 新增/转非 Sheet 默认保留源表全部业务列；PRD 要求联调后冻结字段清单，可在规则引擎中按需裁剪。
- 生产部署应使用 HTTPS；生产环境的会话 Cookie 默认带 `Secure`。若在本地用 http 运行 `npm start` 调试，请在 `.env.local` 设置 `COOKIE_SECURE=0`。
- 本期不包含个税扣缴端自动申报、设备备份迁移、投诉查询、监管报表及与人资/财务系统的自动接口。
- `npm install` 提示 ExcelJS 传递依赖存在若干安全告警（当前环境无法联网执行 `npm audit fix`）；上线前请按集团安全基线评估并锁定依赖版本。
